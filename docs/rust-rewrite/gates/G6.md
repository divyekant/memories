## Part a: the real clients

`server/scripts/gate_g6.sh` starts a new Python server and a new Rust server
with the same settings. Then `parity/clients.py` runs the same client steps
against each server and compares the output of each step. The script masks
the values that change on each run: times, IDs of jobs, ports and temporary
paths.

To run the gate, from the repository root:

```bash
QDRANT_URL=http://127.0.0.1:6333 \
  server/scripts/gate_g6.sh server/target/debug/memories-server
```

The script needs `.venv` (`uv sync --frozen`), `mcp-server/node_modules`
(`npm ci --ignore-scripts`), a Qdrant server, and `jq` for the hooks. A run takes about
1 minute.

| Suite | Client | Steps | What the steps do |
|---|---|---|---|
| mcp | `mcp-server/index.js` over stdio (`server/scripts/g6_mcp.mjs`) | 29 | Lists the tools and calls each of the 18 tools, with error cases |
| cli | The Python CLI `memories` | 51 | Each command that talks to the server: add, upsert, get, list, count, search, links, batch, export, import, admin, backup, extract, sync, delete |
| hooks | Each hook of `plugin/hooks/hooks.json` and `integrations/codex/hooks/hooks.json` | 23 | Runs the script with a hook payload, checks the exit code and the time limit of `hooks.json`, and counts the extract jobs that the hooks send |
| opencode | `integrations/opencode/plugin/memories.js` | 1 | The recall hook and the tool hook |
| installer | `memories doctor` of the npm installer | 1 | The health check and the version line |
| probes | HTTP requests (see part d) | 61 | One request for each status that a Python test asserts and that no golden case has |

A step passes if the two outputs are the same after the masks. A step also
fails on the Rust server if:

- The exit code is not the exit code of the Python server.
- A hook takes more time than the time limit in its `hooks.json`, and the Python
  run did not, or the hook takes more than 1.5 times the limit. The time
  includes the start of bash, jq and curl on a shared CI runner.
- A recall output does not hold a found record (`MUST` in `parity/clients.py`),
  so that a step that finds nothing on the two servers does not pass.
- The hooks send no extract job. The job count itself does not compare,
  because it depends on the timing of the background requests.
- The status of a probe is not the status in its name.

The slowest hook on the Rust server took 0.6 s (`memory-subagent-recall.sh`,
limit 5 s). Each hook with a limit of 1 s took 0.06 s or less.

### Known differences

Each known difference has a record. `KNOWN` in `parity/clients.py` holds the
list. An entry accepts only its own keys: the rest of the output and the exit
code must still be the same.

| Step | Difference | Record |
|---|---|---|
| `cli health` | `version` is 6.0.0. An admin key also gets `extract_queue_depth` and `extract_oldest_job_age_sec`. | Finding 1, `docs/decisions/2026-11-16-rust-extract-queue.md` |
| `cli stats` | `backup_count` counts only the backups that a client asked for. `created_at` is null. | `docs/decisions/2026-11-16-rust-core-writes.md`, row `_backup` |
| `cli backup-list` | No `pre_*` backups, for the same reason. | The same record |
| `cli extract-status` | `queue_max` is 10,000. | `ExtractConfig` in `server/crates/memories-server/src/extract.rs` |
| `installer doctor` | The doctor prints a version mismatch. | Finding 1 |

The script also masks the provider error text of a failed extract job
(`docs/decisions/2026-11-16-rust-extract-pipeline.md`), the queue depth, and
the scores of the search with a recency boost (the boost uses the age of each
record at the time of the search). The order of the results still compares.

### Two defects of the Python reference that the steps avoid

- Python v5.19.0 gives the next add the ID after the highest ID that is left.
  After a delete of the newest record, the two servers give different IDs. Each
  suite adds an anchor record before its deletes, so that the IDs stay the same.
  The Rust server never gives a deleted ID again.
- In the embedded Qdrant mode, two Python snapshots in the same second get the
  same name, and the second one fails with HTTP 500. The gate runs the Python
  server against the Qdrant server.

## Part d: the sort of the Python tests

`python -m parity.sort_tests --write` writes `docs/rust-rewrite/gates/G6-tests.tsv`.
The file has one row for each of the 1,986 test functions of `tests/`. The
`parity` CI job runs `--check`, which fails if the file is old or if an HTTP
test has no check.

| Group | Tests | Meaning |
|---|---|---|
| http | 349 | Sends an HTTP request to the Python app |
| client | 394 | Checks a client with a fake server. Part a runs each client live. |
| tool | 197 | Checks a tool that stays after the cutover (parity kit, eval, scripts) |
| internals | 1,046 | Calls Python code with no HTTP request. The row names the Python modules. |

For each http test, the script finds the routes that the test calls (also
through helper functions of the same file), and each status that the test
asserts. A status has a check if a golden case or a probe has that status on
one of the routes of the test. The other cases are in `parity/g6_checks.json`,
each with a Rust test or a decision record:

| Case | Check |
|---|---|
| `POST /memory/extract` 501 and 429 | Rust tests in `server/crates/memories-server/tests/extract.rs` |
| `POST /memory/merge` 400, `POST /import` 422 | The Python test gets the status only with a mocked engine. Probe `import-200-policy-line`: the real servers agree. Probe `merge-missing-400`: Python gives 500 and the Rust server gives 400, a fixed defect (`FIXED` in `parity/clients.py`). |
| Promotion 200 replies | Promotion is off on the Rust server: `docs/decisions/2026-11-16-rust-promotions-off.md` |
| `POST /sync/download` 404 | Cloud sync is off on the Rust server: `docs/decisions/2026-11-16-rust-sync-off.md` |
| `GET /openapi.json`, `GET /ui/static/*` | Rust test `openapi_is_public_and_has_the_health_version`, golden case `ui-static` and the browser check |

Limits:

- The check is by route and status. It does not compare each assertion of a
  Python test on the body of the reply. The golden cases and the probes compare
  the full body.
- 57 http tests assert no status. For these, a golden case or a probe on any
  route of the test counts. The file marks them "route only".
- The script follows helper functions of the same file. It does not follow a
  request that a conftest helper or a fixture sends.

## Findings

1. **Version.** The Rust server reports version 6.0.0. The clients compare it
   with `mcp-server/assets/backend/BACKEND_VERSION` (5.19.0). `memories doctor`
   prints a mismatch, and `memory-recall.sh` shows "Memories Backend Update
   Available: Running v6.0.0, latest is v5.19.0". The Python test
   `test_backend_version_sources_agree` needs the marker, `/health` and the
   OpenAPI version to move together. Task P7-2 must set `BACKEND_VERSION` to
   6.0.0 in the release. An install that runs the 6.0.0 image with an older npm
   package shows the warning until the package is updated.
2. **No client puts a `/` in a path segment.** The Python server decodes `%2F`
   in a path before it routes the request, and the Rust server does not (known
   gap from task P5-7). The clients send each source prefix in the query string,
   and backup names have no `/`. Thus the gap does not change a client.

## What the gate does not cover

- The Node tests and the smoke scripts of `mcp-server/` use fake servers. They
  do not change with the server, and the `tests` CI job runs them. The live MCP
  suite covers the same tools.
- The remote MCP server (`mcp-server/remote/`) and the legacy Codex notify
  script (`integrations/codex/memory-codex-notify.sh`) are not in part a.
- The hook version check reads `../assets/BACKEND_VERSION`, which exists only
  in an installed plugin. Part a runs the hooks from the repository, so the
  check does not run there. Finding 1 describes its output.
